## 后

> **一句话**：缓存从「存在程序内存里」改成了「存在 Redis 里」。单元测试全部通过。有 1 个集成测试偶尔失败，原因还没找到。
>
> **改了什么**
>
> - 缓存的存放位置：原来用 `cache/lru.py`，把数据存在程序内存里。现在改用 `cache/redis_backend.py`，把数据存在 Redis 里。
> - 缓存的过期时间（TTL）：默认 300 秒。设置环境变量 `CACHE_TTL`，可以改这个值。
> - 用上新缓存的接口：`get_user_profile` 和 `list_orders`。这两个接口的访问量大（原文叫「热点接口」）。
> - 修了一个并发问题，叫「缓存击穿」：一条缓存过期时，很多请求同时去查数据库。现在 agent 用 Redis 的 `SETNX` 命令加了一把分布式锁来解决它。
>
> **测试结果**
>
> - 单元测试：142 个，全部通过。
> - 集成测试：`test_order_pagination` 偶尔失败，跑 3 次失败 1 次。agent 初步判断原因和 Redis 连接池的配置有关，但还没找到根本原因。
>
> **部署时要注意**
>
> 部署时要配置环境变量 `REDIS_URL`。如果不配置，服务不会报错，但会在没有缓存的状态下运行，性能会下降。
>
